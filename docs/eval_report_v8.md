## 指标口径（先读这段，否则数字和旧报告对不上）

| 指标 | 定义 | 为什么这么定义 |
|---|---|---|
| strict@1 | 第一名「命中点名小区 **且** 约束全中」 | 用户同时给了小区和户型/价格，缺一不可 |
| 覆盖@k | top-k 里的合格条数 / min(k, 库内合格集) | 合格集 23 套 vs 1 套的题，「拿满」的含义不同；不按合格集归一，两类题没法比 |
| MRR / nDCG | 按「第一条**真正合格**」的名次算 | 旧口径按「小区名对不对」算，而约束分层把点名小区全排到前面，于是恒为 1.000 |
| 合格精度@k | top-k 里合格条数 / k | 看推荐质量，不看第一名；只判 top1 时库里两居占 36%，随机都能过 |
| 假放宽 | 库内合格集非空却返回了 relaxed | 「已放宽价格」和「第一条在预算内」同时出现，是自相矛盾的输出 |
| 库内合格集 | 全库所有房源按 filters 现算的达标条数 | 题目的难度底座；以前没有它，题目恰好都出在合格集极小的小区上，指标没有区分空间 |

- 合格精度@k：top-k 里「真正满足条件」的比例。semantic 层没有小区名可对，
  只判第一名的户型太宽松（库里两居占大头，随机一条都能过），看这个才有区分度。
- 覆盖@k：只对「给了条件且库里有解」的题统计；空 filters 的语义题没有对错标准，
  混进分母只会把分数洗白（它们恒满分）。

## 发布门禁

| 检查项 | 阈值 | 实际 | 结论 | 含义 |
|---|---|---|---|---|
| mixed strict@1 | >= 0.850 | 1.000 | PASS | 点名小区 + 户型/价格同时答对的比例 |
| semantic 覆盖@5 | >= 0.800 | 0.909 | PASS | 无小区名时，合格房在 top-5 里的覆盖比例 |
| 假放宽（全部层级） | == 0.000 | 0.000 | PASS | 库里有合格房却宣布放宽条件的比例 |
| 零覆盖题数（全部层级） | == 0 | 0.000 | PASS | 库里有合格房，top-k 里却一条合格的都没拿到 |
| 参考：hybrid vs sparse（mixed strict@1） | >= sparse | 1.000 | PASS | 只作参照，不再作为唯一依据（旧门禁恒真就死在这里） |

- 注 1：题目自带 filters，评测直接喂给检索，所以这一层只衡量排序，不掺抽取。
- 注 2：`hybrid` 与 `hybrid_nofilter` 在 mixed 层的差值 = 「约束排序」本身的贡献。
- 注 3：strict@1 = 第一名「命中点名小区 **且** 约束全中」，判定调线上同一函数。
- 注 4：索引为**全量** 38266 条房源（覆盖 4900 个小区、13355 个「小区 × 户型」组合），不再抽样——16000 条时代有 58.2% 的房源永远检索不到（双龙南里两居只能给 1 套 / 实际 5 套）。
- 注 5：门禁阈值是**绝对**的，不再用「hybrid >= sparse」这种两边都满分、恒为真的比法。
